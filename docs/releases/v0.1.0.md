# University Agent v0.1.0

> Draft release notes. Publication remains pending until the project owner
> selects and applies a distribution license.

University Agent v0.1.0 is the initial public MVP. It combines deterministic,
read-only academic workflows with a local-first command-line agent. This release
does not promise a stable public Python API; interfaces may evolve in later
versions.

## Highlights

- Packaged `university-agent` command with local Ollama as the default provider.
- Read-only Gmail OAuth integration using only the `gmail.readonly` scope.
- Deterministic parsing of supported deadline and course-notice subject formats.
- Upcoming-deadline and recent-course-notice application workflows.
- Local TXT and embedded-text PDF discovery, extraction, chunking, caching, and
  lexical retrieval.
- Host-controlled source provenance using course names, relative paths, and PDF
  page numbers when available.
- Optional OpenAI Responses API adapter with the same narrow tool boundary.
- A reproducible demo built entirely from fictional TXT materials.

## Install from a source checkout

Python 3.12 or newer is required.

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install .
university-agent --help
```

For the live fictional-material demo, install and run Ollama separately and
make `llama3.2:3b` available. Then, from the source checkout:

```bash
university-agent \
  --materials-root examples/materials \
  --timezone Europe/Madrid \
  "Explícame exclusión mutua usando mis apuntes"
```

The fictional demo does not require Gmail credentials or an OpenAI API key.

## Privacy and security

- Gmail access is read-only and OAuth credentials remain local and Git-ignored.
- Local materials are read only from the user-selected root.
- The documented Ollama path keeps normal inference local; a remote Ollama host
  changes that privacy boundary.
- OpenAI is optional and must be selected explicitly.
- Agent-facing results omit absolute paths, Gmail message identifiers, and raw
  credential data.

## Current limitations

- Moodle is not integrated.
- Gmail-derived deadlines cover only explicitly supported subject formats and
  are not an authoritative task list.
- Local retrieval is lexical, not semantic search or RAG.
- DOCX, PPTX, OCR, scanned PDFs, persistence, and calendar integration are not
  supported.
- Source references identify retrieved passages but are not sentence-level
  citation alignment.
- The Python API is an initial MVP surface and is not yet guaranteed stable.
